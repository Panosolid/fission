# Kernel

Rust geometry kernel, compiled to WebAssembly with wasm-pack. Read with the root CLAUDE.md (top rules, general testing rules, git workflow).

## Modules (each file's top comment has the rest)

- `src/tolerance.rs`: every tolerance and the exact predicates; the only place epsilons live.
- `src/fmath.rs`: sin, cos, atan2, hypot and the other maths beyond + − × ÷ √, through the pure-Rust `libm`, so the browser and native builds give the same bits; kernel code calls these, never the `f64` methods (`clippy.toml` refuses them).
- `src/geom/`: curves (`curve.rs`: Line, Circle), surfaces (`surface.rs`: Plane, Cylinder, Sphere), similarity transforms (`transform.rs`), placements (`placement.rs`: rotation as a unit quaternion plus a shift, kept apart from geometry).
- `src/topology.rs`: B-rep arenas (Vertex, Edge, Coedge, Loop, Face, Shell, Body) and Euler counts; each face's `role` (`FaceRole`, step 24b: an extrude's Start, End and Side of each given piece; a box's six directions; a cylinder's Bottom, Top, Side; a sphere's Upper, Lower), kept through moves and turns.
- `src/validate.rs`: `validate()` and `checked()`; every operation's result goes through `checked()`. Each `ValidationError` has a `category()` (topology, geometry, solid; B0 decision 8), and every report lists errors grouped by it (`report_lines`).
- `src/self_intersect.rs`: the self-intersection check `validate` runs (edge–edge, edge–face, face–face), measuring candidates from `src/intersect.rs`, which only proposes points, never decides that two things touch.
- `src/placed.rs`: `Placed` = local geometry plus placement; moves and turns change only the placement; `baked()` gives world geometry where it is needed.
- `src/tessellate.rs` (watertight mesh, constrained Delaunay in uv via `spade`), `src/mesh.rs` (mesh volume with double-double determinants, area, closed check), `src/accurate.rs` (double-double arithmetic, and `Exact` sums for the exact area sign), `src/display.rs` (per-face normals, edge lines for the viewer).
- `src/mass.rs`: exact volume and area from the B-rep's edges, keeping digits far away and at huge radii. The app shows these, not mesh values.
- `src/face_mass.rs`: each face's exact area and centroid (step 24b; sphere and cylinder from the vector area, planes by Green's theorem with each arc's segment), and `mesh_face_moments`, the mesh route the tests compare with.
- `src/stl.rs`: binary STL export (reports the largest rounding to single precision, warns past MIN_FEATURE) and reading it back.
- `src/ops/`: `primitives.rs` (box, cylinder, sphere), `profile.rs` (lines, arcs as bulges, circles, and their validity rules), `extrude.rs`, `transform.rs` (move, rotate on `Placed`; a rotation pivot must lie in model space), `place.rs` (step 26b: an extrude built in a frame, origin + x axis + normal with y = normal × x, so always rigid; frames off unit or square by more than `FRAME_SQUARE` refused; `flip` goes the other way from the same plane, built as the mirrored profile in the frame seen from behind, so its start cap stays on the sketch plane). Each returns `Result<Body, KernelError>` via `ops::finish`, and has a `_meshed` form that also returns the display mesh its validation built (`validate::checked_meshed`); `lib.rs` uses those, so the app's calls validate and tessellate a body once (a new operation gets both forms).
- `src/sketch.rs`: the first part of the 2D curve library (K1, step 21a): grid snapping (`snap_to_grid`), free placement (`place_freely` to `free_spacing(pixel)`, the largest power of ten no bigger than a screen pixel, sketch feel SF1), the rules for sketch lines (`check_lines`), circles (`check_circles`, step 22b) and arcs (`check_arcs`, step 23a: counter-clockwise from start to end round a centre within LINEAR of their midway line; `Arc::bulge` from the sagitta), and the one closed outline a sketch's lines, circles and arcs make or why they make none (`sketch_outline(lines, circles, arcs)`: one lone circle is a circle outline; an arc walked from its end gets its bulge negated; checked by the profile rules, so a closed sketch always extrudes; with each piece's `Source`, the curve it came from and whether it is run backwards, step 24b).
- `src/fixtures.rs`: hand-built test bodies (cube, cylinder, sphere, half cylinder, tube, sphere cap/slice/octant, `two_shells`) that don't use `ops`.
- `src/api_error.rs`: `ApiError`, what a failed call tells the app: `kind` (invalid-input, invalid-result, bad-request, unknown-body, too-many-bodies, internal), `inputs` (`ops::Input`: which argument, profile loop or piece, or sketch line, arc or circle is at fault; every `KernelError::InvalidInput` carries them) and the message, unchanged from when errors were plain text.
- `src/store.rs`: the body store (24c+): bodies kept between calls by handle (from 1, never reused, below 2^53), each with its display mesh; never changed in place, so an operation on a stored body makes a new one; at most `MAX_LIVE_BODIES`; `live()` for leak checks.
- `src/lib.rs`: the thin `#[wasm_bindgen]` API (`make_box`, `make_cylinder`, `make_sphere`, `make_extrude` → `BodyView` with exact volume and area, and each face's role, area, centroid and (planes) outward normal, and each edge's two faces (`edge_faces`, the one walking it forwards first); `export_stl(spec, name)` → `StlFile`, a `BodySpec` naming the same shapes (an extrude's may carry a `frame` and `flip`, `ops/place.rs`; built as `Placed`, so the view and STL come out placed); `snap_to_grid(x, y, spacing)` and `place_freely(x, y, pixel)` → `[x, y]`, and `sketch_outline(lines, circles, arcs)` → `{ closed: profile }` (a path or a circle, with `pieces`: the curve each piece came from) or `{ open: why }`; the store: `body_build(spec)` → handle, `body_view`, `body_stl`, `body_free`, `body_count`). Every failure is thrown as an `Error` carrying `kind` and `inputs` (`api_error.rs`). Keep it thin.
- `src/debug_dump.rs`: failure dumps (ASCII STL per body + an offline `index.html`; dashed red: a named edge's own curve). `checked` writes one (`dump_invalid`, at most 20 per process) into `target/failure-dumps/` before panicking and names it in the panic; the harness writes its own there too; `endless.sh` copies them into each nightly failure folder; `examples/dump_demo.rs` writes the two dumps the browser check opens.
- `tests/stateful.rs`: the stateful random-testing harness (see its header). When a kernel operation lands, add it to `Op`, `Scene::transitions`, `apply_op` and `replay_op` the same day.
- `tests/fuzz_stl.rs`: fuzzing the STL reader (`stl::read`, `welded`) against a model of the format; quick in `cargo test`, long in the nightly `fuzz.yml` (`FISSION_FUZZ_SECONDS`, `FISSION_SEED`, `FISSION_FUZZ_OUT`); failing inputs saved in `tests/regressions/fuzz-stl/*.stl` replay forever.
- `tests/scale_sweep.rs`: the whole modelling range through `view_of` and `stl_of` (testing hunt 3c): both ends by hand, every length at 0.9×/1.1× of its limits, three profiles every quarter decade from 1 µm to 1 km in frames up to 90 km out, and 5,000 seeded near-tangent holes (`FISSION_SEED`).
- `tests/boolean_cases.rs`: the boolean nasty-case generator (step 30c, `tests/support/boolean_cases.rs`): seeded pairs of boxes and turned prisms in every flat family of the catalogue (Boolean test plan) at the origin, 1 km, 100 km and micrometre size, with each family's intended outcome, as JSON lines (`FISSION_BOOLEAN_CASES_OUT`, `FISSION_SEED`, `FISSION_BOOLEAN_SEEDS`) for `../prototypes/boolean/judge.py`; the kernel's own answers join them at 35.
- `tests/worst_case.rs`: wall-clock budget for the costliest legal extrude (a 100 m plate with 1,996 round holes, every circle at the chord cap), end to end as `make_extrude` runs it; its own test binary so it runs alone.
- `fuzz/`: coverage-guided fuzzing (cargo-fuzz, nightly Rust): `checks.rs` holds one check per target (`extrude`: any profile, then view, mesh and STL, volume and area against the profile's own, every face's role and the caps' areas and centroids, every edge's two faces against the loops (`check_edges`, also in `sketch`); `sketch`: lines, arcs and circles, a closed outline must extrude and name each drawn curve once, between its corners; `placed`: moves and turns, then mesh and bake), `fuzz_targets/` hands them to libFuzzer, `seeds/<target>/` is the minimised corpus each run starts from, `run.sh` is one nightly round (`fuzz.yml`). `tests/fuzz_corpus.rs` replays the seeds and every saved crash (`tests/regressions/libfuzzer/<target>/`) through the same checks in every `cargo test`, on stable. `answers.rs` and `same-answer/` (`check.sh`, in CI's `kernel` job): every saved input's exact answer from native release, native test and WebAssembly builds must match to the bit.
- `tests/regressions/`: proptest failure seeds and `stateful/*.json` minimal failing chains (committed; replayed forever by `saved_regressions_still_pass`).
- `scripts/overnight.sh` (Tier 3 run), `scripts/endless.sh` (the same, round after round with random seeds, into `endless-results/`).
- `../prototypes/boolean/`: exact models of booleans, the referees for 31–36 (`box_model.py`, unions of boxes; `convex_model.py`, turned convex prisms), and `judge.py`, which judges a line's answer against them after snapping places within 2·LINEAR (rule 1), with `--model-answers` and `--planted` self-tests (CI's kernel job).
- `../prototypes/oracle/compare.py`: OpenCascade oracle comparison for bodies the harness writes (box, cylinder, sphere, extrusion).
- `../prototypes/oracle/sketch_outline.py`: an independent model of `sketch_outline` (exact fractions for lines; arcs walked exactly and measured for faults); `sketch_outline_check.py` runs 10,000 seeded sketches (polygons, broken ones, 0.9×/1.1× threshold cases, arcs, circles) through `examples/sketch_outline_json.rs` (the app's `sketch_outline_of`, numbers passed as bits) and needs every answer to agree; `test_sketch_outline.py` (CI's `kernel` job) holds the hand-worked cases, that run, and planted breaks it must catch.

## Commands

- Tier 1, after every change: `cargo clippy --all-targets && cargo test <module>` (plus `cargo check`).
- All kernel tests: `cargo test` (must show 0 failed, 0 ignored). Run them in a debug build: in `--release`, `validate::tests::checked_panics_in_test_builds` and `checked_writes_a_failure_dump_before_panicking` fail on purpose, because invalid results only panic when `debug_assertions` is on.
- Before pushing kernel changes, also build for the browser: `cargo build --target wasm32-unknown-unknown` (code gated with `#[cfg(not(target_arch = "wasm32"))]`, like `debug_dump`, must not be called from code built there). CI uses the latest stable Rust, whose clippy may have lints the local toolchain lacks: `rustup update stable` first.
- After every push that changes `kernel/`, start a "Random testing" run on the pushed branch (GitHub Actions, `nightly.yml`, workflow_dispatch with `ref` = the branch). The scheduled run tests only `main`, nightly from 11pm to 7am Perth (15:00–22:35 UTC, hard cut-off): 8 jobs of `endless.sh` in two legs (`scripts/run-until.sh`), plus cargo mutants over the whole kernel in 4 shards; so unmerged work is tested only by these dispatched runs (tick `mutants` to include mutation testing). Results accumulate on the `test-results` branch: `summary.txt`, `log.csv` (with `commit` and `branch` columns naming the code each round tested), `failures/<seed>/` (with `commit.txt`), `mutants/` (`missed.txt`: every survivor of the last complete mutation run; `log.csv`: one line per run); one issue per kind of problem, labelled `random-testing` (`.github/scripts/file_issues.py`: a new kind gets an issue, a known one a comment per run, one closed as fixed is reopened if it comes back on `main`, one closed as not planned is left alone), and one when a mutant survives that the previous complete run did not have (compared without line numbers). Close a kind's issue as completed with the fix and its regression test, or as not planned with the reason (OpenCascade's own rounding, say). A failure from an older commit may already be fixed or out of range. The oracle compares SpindleLabs with the exact volume and area (`prototypes/oracle/exact.py`, 50 digits); where only OpenCascade is off, that is its rounding and is not counted. Mutation shards get up to 330 minutes even in a dispatched run, so a ticked `mutants` always finishes (~75 minutes a shard).
- Stateful random testing, quick mode (~200 cases, ~50 s, also part of `cargo test`; ~95% of operations in range, ~5% with one extreme input, counted in the report's "~extreme input" row): `cargo test --test stateful -- --nocapture`
- Speed and memory baseline: `python3 .github/scripts/baseline.py` (repo root; needs valgrind and the WASM build) runs `examples/baseline.rs` (peak heap and allocations per key operation from a counting allocator; instructions from callgrind) and the app's `packages/testing/baseline/app.ts`, and compares with `tests/baseline.json`; CI's `baseline` job fails past the margins written in that file (15%). A new key operation gets a line in `examples/baseline.rs`; the baseline changes only with the owner's OK (`--update`).
- Precision measurement: `cargo run --release --example precision_budget` (how far intersection points land from both pieces, by part size and distance from the origin; evidence for the modelling range).
- Mutation testing: `CARGO_PROFILE_DEV_OPT_LEVEL=0 CARGO_PROFILE_DEV_DEBUG=0 cargo mutants -f src/<file>.rs -j 4 -- --lib` (install once per container: `cargo install cargo-mutants --locked`; not while `rustup update` runs). The two variables make each mutant's build about five times faster than the default opt-level 2 builds, which dominate the run (829 mutants: 40 min instead of ~5 h); the lib tests stay debug builds, so the result is the same. Speed tests time the code against a reference pass in the same build (as `display::tests::many_faces_and_triangles_cost_one_pass` does), never against the wall clock alone, so they hold in these unoptimised builds and mutant runs keep them.
- Endless mode (owner's own computer, no Claude involved; random seed per round until Ctrl+C, results in `endless-results/`): `scripts/endless.sh [cases-per-round] [rounds, 0 = endless] [python]`
- Overnight mode (100,000 cases × 4 seeds in release, then the OpenCascade oracle): `scripts/overnight.sh [cases] [seeds] [python]` (needs `pip install cadquery-ocp`)
- Coverage-guided fuzzing (install once: `rustup toolchain install nightly --profile minimal && cargo install cargo-fuzz --locked`): `cargo +nightly fuzz run -a -s none <extrude|sketch|placed> fuzz/corpus/<target> fuzz/seeds/<target> -- -max_total_time=600 -timeout=20`. `-a` keeps debug assertions (invalid results panic), `-s none` skips AddressSanitizer (safe Rust; its build answered one profile check differently, see `fuzz/run.sh`). A crash goes into `tests/regressions/libfuzzer/<target>/` under a name saying what it is; refresh the seeds with `cargo +nightly fuzz cmin -s none <target> fuzz/seeds/<target>` after a long run.
- `wasm-opt` is disabled in `Cargo.toml` because the sandbox can't download binaryen. Harmless; re-enable when size matters.

## Supported modelling range

Every serious kernel works inside a fixed range (commercial kernels commonly use a 1 km box). SpindleLabs's:
- Feature sizes (any length parameter: width, radius, distance, and a profile's overall span) from 1 µm to 1 km: `tolerance::MIN_FEATURE` = 1e-3 mm to `tolerance::MAX_SIZE` = 1e6 mm. Model sizes must be within (LINEAR, MAX_SIZE]; `ops::check_length` enforces this for every length input.
- Every point of every body within ±100 km of the origin: `tolerance::MAX_COORD` = 1e8 mm. That far out a double resolves 2⁻²⁶ mm (~15 pm, a thousandth of LINEAR), fine for placing a body but too coarse to intersect there, where shallow crossings magnify the rounding.
- Linear tolerance 10 nm (`LINEAR` = 1e-5 mm), 100× below the smallest feature. Chosen with the owner during step 15, while the self-intersection check was being built (commit a625416, replacing 10 km / 1 nm), from measurements: `examples/precision_budget.rs`, and `intersect::tests::the_modelling_range_leaves_room_for_rounding`, which fails if LINEAR or MAX_SIZE move past what doubles support (it fails for 1 nm at 1 km, 10 nm at 10 km and 1 nm at 10 km). At 1 km, crossings steeper than 0.6° land ~300× inside LINEAR, but 0.06° to 0.6° crossings can slide 0.4 LINEAR along the curve: booleans must handle shallow crossings with care (step 36).
- Geometry is intersected near its own origin. Before booleans (step 35), when two bodies meet, bake them into a frame centred on them, not the world frame: at 100 km out, the position alone costs ~0.07 LINEAR per intersection at shallow crossings.
- There is no rule on the ratio of smallest feature to part size yet (the cap makes it at most 1e9). Measure again at step 35, when the volume formula for turned, baked thin parts is rewritten.
- Operations outside the range return `KernelError::InvalidInput`; they never panic and never produce geometry.
- Volumes, areas and projections are computed relative to a local origin (the body's or mesh's bounding-box centre, or a point on the face), never the world origin.
- The fuzzer spends ~95% of its inputs inside the range and ~5% on extreme inputs, which only have to produce clean errors.

## Planned for the integration work (owner's decisions, docs/integration.md)

- One 2D curve library for the sketcher, Vector, Laser and Layout lives here (lines, arcs, Béziers, offsets, path booleans, biarc fitting, later the solver's geometry), using `tolerance.rs`; each operation joins the stateful harness the day it lands, like any other.

## Conventions

- Units are millimetres. Z is up (the viewer sets `Object3D.DEFAULT_UP` to +Z).
- A face's outward normal is its surface's natural normal (∂u × ∂v), flipped when `sense` is false. Cylinder and sphere natural normals point away from the axis/centre.
- Loops run counter-clockwise seen from outside, so the face interior is on the left of every coedge (normal × tangent points into the face). The first loop of a face is the outer one when it has one.
- Every edge is used by exactly two coedges, once in each direction. Edges run start → end over t0 < t1; full circles are closed edges with start == end and no seam vertex. Cylinder side faces have no seam edge; they have two loops.
- Euler–Poincaré per shell: V − E + F − R = 2(1 − genus), where R counts inner loops.
- Tessellation: edges are discretised once and shared by both faces, so meshes are watertight by construction. `TessOptions::refine` multiplies every curved segment count (used for Richardson extrapolation of mass properties).
- Invalid results panic in debug/test builds (they are bugs) and return `KernelError::InvalidResult` in release.

## Crash-freedom (top priority)

- No kernel operation may panic on any input: bad input returns `KernelError::InvalidInput`, never silently broken geometry.
- Cost must be bounded for every legal input (e.g. `MAX_SEGMENTS_PER_TURN`).
- Use `geom::unit` (not `normalize`) on any user-supplied direction: lengths can overflow or underflow.
- In the harness, a check must verify what an operation did (independent position tracking), not only invariants it preserves.

## Kernel testing rules

### Validate after every operation
Every kernel operation (primitive, extrude, revolve, boolean, fillet, shell, import) must end with validate(solid), which checks:
- Watertight: every edge is shared by exactly two faces
- Consistent orientation: all face normals point outward
- Euler–Poincaré holds (V − E + F − R = 2(1 − genus) per shell)
- Every vertex lies on its edges, and every edge lies on its faces, within tolerance
- No zero-length edges, zero-area faces, or self-intersections

In debug and test builds, validation runs automatically and panics on failure. When adding a check to validate(), also add a test that breaks a valid body in exactly that way and asserts the specific error.

### Tolerance
- One global tolerance system: `src/tolerance.rs`. Never hard-code epsilon values anywhere else.
- Use exact/robust predicates (the `robust` crate) for orientation and in/out tests.
- Every test that compares floats uses the tolerance system, never `==`.

### Tier 1: fast checks (after every change, under 30 s)
- The Tier 1 command above: unit tests for the changed module only.
- Unit tests for maths: curve/surface evaluation, derivatives, normals, transforms, intersections against hand-calculated answers.

### Tier 2: property tests (before calling a feature done, under 5 min)
Use proptest for properties that must always hold:
- Booleans: vol(A ∪ B) = vol(A) + vol(B) − vol(A ∩ B); A − A is empty; A ∪ A = A; A ∩ B = B ∩ A
- Transforms don't change volume or surface area
- Extrude: volume = profile area × distance
- Round trips: export → import gives the same topology and geometry within tolerance (native format and STEP)
- Rebuild determinism: rebuilding the same timeline twice gives identical results

Include nasty cases on purpose: coplanar faces, touching edges, shared vertices, tiny overlaps, near-tangent surfaces, very large and very small sizes.

### Tier 3: overnight suite (only on schedule or when asked)
1. Large property-test runs (thousands of cases per property, multiple seeds).
2. Oracle comparison with OpenCascade (Python + cadquery/OCP): volume, area, face count, bounding box. Log disagreements for review; OpenCascade isn't always right either.
3. Golden models in `tests/golden/` (brackets, enclosures, gears, phone case): rebuild and compare to the saved result.
4. Simulated user sessions: a bot builds random models (sketch → extrude → cut → fillet → pattern), edits an early timeline step and rebuilds. Record % rebuilding without errors, % where later features still attach to the right face/edge, % passing validate(), and rebuild time vs feature count.
5. Performance: booleans, rebuilds and tessellation on the golden models.

### Mutation testing
`cargo mutants` finds code that no test notices being broken. Every surviving mutant in kernel code gets a test, or is listed as equivalent, with the reason, in a "Mutation testing (...) leaves these survivors" paragraph at the end of the file's top `//!` comment (see `mass.rs`, `ops/profile.rs`). CI runs it on every pull request over the kernel code the change touches (`mutants-in-diff` in `ci.yml`, `cargo mutants --in-diff`, lib tests) and fails, holding the merge, on any survivor; so an equivalent survivor also goes into `.cargo/mutants.toml` (`exclude_re`, with the reason beside it), which the nightly run reads too. cargo-mutants never mutates functions named `new`, so logic in a `new` (such as `Placed::new`'s re-centring) needs its own tests or a differently named helper. CI's `coverage` job (`cargo llvm-cov`, report only) lists per file which kernel lines no test runs.

### Visual debugging
When a geometry test fails, export the failing shape(s) as STL plus a small HTML viewer page with the problem edges/faces highlighted (`src/debug_dump.rs`).

## Boolean design (B0 decisions)

Made at step B0 (2026-10-16); the owner confirmed decisions 2 and 5 the same day, with the refinements written into them. No boolean code goes against these without changing this section first.

1. **P-curves.** Until step 37, uv computed on demand from the 3D edge is exact: a line or circle on a plane is a line or circle in uv; on a cylinder a line along the axis is u = const and a circle round it is v = const; on a sphere a parallel is v = const and a meridian is u = const. That stops holding at step 37 (an ellipse on a cylinder is a sine-like curve in uv, and on-demand uv can't tell which side of the seam a curve crossing it is on). From step 37 every coedge on a curved face stores its p-curve (its edge drawn in the face's uv), including which period of u it uses; planar faces may keep computing uv. Validate checks that surface(p-curve(t)) lies within the edge's tolerance of the 3D curve. Reason: face splitting and point-in-face then work in 2D on every face, which is the standard approach and the only one that handles seams.
2. **Model contract.** A body is one closed, orientable, 2-manifold solid: every edge used exactly twice (once each way) and the faces round every vertex form a single fan. The decision is made on the result, not the operation: whenever a boolean's output would share an edge or a single vertex non-manifoldly (two boxes unioned while touching only along an edge or at a corner, a cut leaving two pieces joined only along an edge), it returns `KernelError::NonManifoldResult` carrying where the touching edges and vertices are, which the app highlights through the overlay format, with a message saying to overlap or separate the parts by at least MIN_FEATURE. It never returns separate bodies or a non-manifold body. Results that are manifold are not errors: a subtract whose tool only touches A returns A unchanged, and an intersect of parts that only touch has zero volume, so it returns no bodies. Reason: fillets, shells, STL and every later algorithm assume a manifold; most kernels refuse such results in solid modelling (SolidWorks reports "zero-thickness geometry"); a silent split can hide a design mistake and is easy to add later (roadmap: an optional "keep as separate bodies"). Validate gains the vertex-fan check at step 36, with a test that breaks it.
3. **Several pieces and voids.** A boolean returns a list of bodies, one per connected solid piece (a cut that splits a part gives two bodies, as in Fusion). Inside one body, `shells[0]` is the outer shell (positive enclosed volume) and any further shells are voids: inward-facing (negative volume), each strictly inside the outer shell, none inside or touching another. Validate's inside-out check becomes "outer positive, voids negative and contained" at step 35, with a broken-input test for each part (void outside, void inside a void, void facing outward).
4. **Curve types.** New exact curves, each added the step it is first needed, with evaluation, derivatives and closest-point inversion: `Ellipse` (a slanted plane through a cylinder, 37); a procedural intersection curve (38) for two quadric surfaces where one is a cylinder: a point is "angle θ round cylinder A, height from the quadratic that puts it on surface B", exact in closed form (one square root), with derivatives by the chain rule. Each edge is one branch of that quadratic between two turning points (where the two roots meet), and near a turning point the piece is parametrised by the other surface's angle instead, where it is well conditioned. Simple cases get their own exact types instead of the procedural curve: circles for coaxial cylinders and spheres and for a plane square to a cylinder's axis, lines for parallel cylinders and for a plane parallel to the axis, a circle for plane–sphere and sphere–sphere, and two ellipses for the equal-radius tee (step 38; they cross at two points, which become vertices with four intersection edges meeting, which face splitting must accept). Radii within LINEAR of each other count as equal; the nearly-equal case (the curve almost pinches) is the procedural curve with the parametrisation switch. Cones and tori (42) add conics as needed. Surface pairs with no closed form (cylinder–torus, plane–torus in general position, cone against most surfaces) get the general procedural crossing curve at 43, before the fillets (44–46), since fillet pieces along an edge chain are trimmed against each other and a cut through a filleted part meets a torus (B0r, 2026-10-23; it replaces "wait for NURBS"): the curve is defined by its two surfaces and a chain of seed points, every evaluated point re-solved by Newton onto both surfaces to within the edge's tolerance, with derivatives by implicit differentiation; a crossing the marching cannot follow cleanly returns `KernelError::InvalidInput` naming the faces. Until 43 such pairs return `InvalidInput` saying the combination is not supported yet. No polylines or fitted splines, before or after NURBS: a curve's stored data are exact surfaces and seeds, never an approximation of the curve. Reason: "exact B-rep geometry"; this is the curve the self-intersection sampler (`intersect.rs`, around_cylinder) already computes.
5. **Tolerance model.** Vertices and edges carry their own tolerance, defaulting to LINEAR; faces don't. Only an intersection may grow one, to the distance it actually measured, and never above a cap of 10 × LINEAR (100 nm, still 10× below MIN_FEATURE, and about a thousand times finer than a printer or CNC machine makes); a result that would need more returns an error, never silently exceeding it. Validate checks each vertex and edge against its own tolerance (a vertex's tolerance covers the gaps to every edge end it joins). Two entities are within tolerance of each other when their distance is at most the sum of their two tolerances; a face has none, so a vertex against a plane uses the vertex's (B0r, 2026-10-23). A boolean may grow a new entity up to max(the cap, the largest tolerance of the inputs it came from); it accepts inputs with entities up to MIN_FEATURE / 2 (500 nm, so that two entities that count as the same can never be a legal feature apart) and refuses looser ones with `InvalidInput` naming the entity, which is the limit import (75–76) must heal a file down to. The default and the cap are constants in `tolerance.rs`; per-entity values are data. The fields arrive at step 31 (all LINEAR) so boolean code never reads LINEAR directly. Reason: intersection edges never lie exactly on both surfaces (near-tangent crossings, the square root near a turning point, later STEP files that bring their own tolerances); one global value would have to be loosened for everything. Growth is watched, not just allowed: many edges creeping towards the cap means something is losing precision and needs fixing, not allowing for (test plan: the nightly tolerance report and the compounding check). Correction to the readiness check: the measured shallow-crossing slide is 3.9 nm along the curve (0.4 LINEAR, `tolerance.rs`), not 3.9 µm; per-entity tolerance is needed for the reasons above, not that number.
6. **Tidying results.** After every boolean, neighbouring faces on the same surface are merged, and edges on the same line or circle meeting at a vertex used by only those two edges are joined. Slivers and tiny edges are never silently removed: a result with a face narrower than or an edge shorter than MIN_FEATURE returns an error naming it. Reason: healing moves geometry silently, and silent geometry bugs are the worst kind. Every boolean returns a history map (for each output face and edge: the input faces/edges it was modified from or generated by, and which inputs were deleted), and splits and merges both report through it, so step 24's IDs must allow one-from-many and many-from-one; step 55 builds on that map.
7. **Classification and predicates.** Point-in-face works in the face's uv (decision 1): a winding-number test against the p-curves, unwrapped across the seam. Every in/out answer is three-valued: IN, OUT or ON (within tolerance of the boundary), and ON is never forced into IN or OUT; ON cases go to the coincidence code (36). Plane predicates stay exact (`robust`), and have one authority above them (B0r, 2026-10-23): whether two things are the same or apart is decided once, by the tolerance test in the boolean's facts table; predicates only order or side things the table already separated by more than their tolerance, and no later stage makes a vertex or measures a distance of its own (a crossing the table does not know is `InvalidResult`). Predicates on curved surfaces use a floating-point evaluation with a worked-out forward error bound: if the value is bigger than the bound the sign is certain, otherwise the answer is ON. No interval-arithmetic library. Body-level classification (is this face of A inside B?) casts a ray from a face interior point in a seeded direction; if it passes within tolerance of an edge or touches a face tangentially, it retries with the next seeded direction, a bounded number of times, then returns an error. Reason: deterministic, bounded cost, and a near-miss is always seen as one instead of a coin flip.
8. **Validation in four categories.** Every `ValidationError` belongs to one category, reported with it: topology (references, closed loops, edge use, shells connected, Euler–Poincaré, vertex fans), geometry (vertices on edges, edges on faces, p-curves on their edges, each within its own tolerance, no zero-length edges or zero-area faces), solid (orientation, inside-out and voids, self-intersection), and operation correctness, which lives in the tests rather than `validate()` (the boolean identities, the oracle). Each check keeps a broken-input test asserting its exact error. The self-intersection check's limit on cylinder faces with other boundaries (`self_intersect.rs` header) is lifted at step 37 by classifying in uv through p-curves.

### Boolean test plan (world-class standard; each item lands with the step that makes it testable)
- Nasty-case catalogue, written as tests before the code that handles them, at 0.9× and 1.1× of every threshold involved: coplanar faces (same and opposite sense), faces touching along an edge or a vertex, shared vertices, a box sitting exactly on another, tiny overlaps (MIN_FEATURE and 1.1× LINEAR), near-miss (0.9× LINEAR apart), a cylinder tangent to a plane, coaxial cylinders of equal and different radii, a sphere kissing a face, the equal-radius tee, nearly-equal radii, crossings at shallow angles (0.06°–0.6°), a hole drilled exactly through an edge or a vertex, nearly parallel planes crossing at an angle between ANGULAR and 1e-6 rad (vertices far from the crossing line are ON both planes), a shallow crossing through an edge of the other body at 1 km (the slide's rounding is near the cap: a clean result or the cap error, never a wrong answer), a box wholly inside another and two boxes apart (no facts at all, the ray path), and the same cases at 1 km and 1 µm and 100 km from the origin.
- Hand-worked cases with the working shown: volumes of box ∪ box, box − cylinder (a drilled hole: L·W·H − πr²H), the Steinmetz solid (two equal cylinders crossing at right angles intersect in 16r³/3), sphere ∩ half-space (cap volume πh²(3r − h)/3), and the face, edge and vertex counts of each.
- Property tests (proptest, seeded): vol(A ∪ B) = vol(A) + vol(B) − vol(A ∩ B); A − A is empty; A ∪ A = A; A ∩ B = B ∩ A; (A − B) ∪ (A ∩ B) = A; moving both inputs together moves the result; every result passes validate in all four categories.
- OpenCascade oracle (`prototypes/oracle/compare.py`) on every boolean the harness makes: volume, area, face count, bounding box; disagreements logged for review, since OpenCascade is wrong sometimes too.
- Every boolean joins the stateful harness and the nightly random testing the day it lands, plus cargo-fuzz (35); each shrunk failure is kept in `tests/regressions/`.
- Non-manifold results: tests that union and subtract along a shared edge and at a shared corner return `NonManifoldResult` naming that edge or vertex, that a subtract whose tool only touches A returns A unchanged, and that an intersect of touching parts returns no bodies; each at 0.9× and 1.1× LINEAR apart.
- Tolerance growth: the nightly summary reports how many edges and vertices grew past LINEAR, the largest, and how many came within 2× of the cap, compared with `tests/baseline.json` like any metric. A compounding check: the harness's operation chains feed boolean results back into further booleans and fail if any tolerance keeps growing from step to step instead of staying at what its own intersection measured.
- Mutation testing on every boolean module, survivors killed or listed as equivalent.
- Golden models (28) rebuilt nightly with booleans in them, and their metrics in `tests/baseline.json`.
